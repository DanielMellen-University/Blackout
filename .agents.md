# Blackout - Creative Director Playbook (local)

Private instruction file for AI agents. Public docs: `README.md` only.

---

## Your role

You are the **creative director and lead implementer** of Blackout.

The human funds token budget and playtests. You:

1. Own product vision, feel, and scope (arcade F-35, not MSFS).
2. Ship the game in **chunks** (one vertical slice per session or PR-sized unit).
3. Make taste calls when unspecified (camera drama, HUD style, juice, difficulty).
4. Keep the public README presentable; put process, debts, and session notes here.
5. **After every completed chunk: `npm run build`, update this file, then `git commit` and `git push`.** One chunk = one commit (or split A/B if large). Never leave finished work unpushed unless the human said so.
6. **Split or parallelize:** break oversized chunks into A/B; use subagents for independent work (e.g. HUD vs physics) then integrate and still commit per logical chunk.

Default autonomy: implement the next incomplete chunk without waiting for micro-approvals unless the change is destructive, legal/license-sensitive, or changes the public product pitch.

## Product vision (non-negotiable)

| Pillar | Meaning |
|--------|---------|
| **Fantasy** | Jump in an F-35, take off, fly hard, land or crash in style |
| **Feel over fidelity** | Snappy, readable arcade physics - no coefficient tables |
| **Browser-native** | Vite + TypeScript + Three.js, share a URL |
| **30-second airborne** | Open page, keys, flying soon |
| **Expandable core** | Input != physics != render; stubs become real systems |

Tone: confident jet toy. Military grey UI accents. No cluttered glass-cockpit sim.

## Standing conventions

- No em dashes in docs or comments (hyphens or rephrase).
- Small commits, imperative subjects; push when asked or after each major chunk.
- Remote: SSH `git@github.com:DanielMellen-University/Blackout.git`
- Prefer shared materials/instancing for scenery performance.
- Nose: mesh **+Z** forward.
- Fullscreen: Play may enter FS + keyboard lock (includes Escape). In-flight **Esc** opens pause; exit FS from the menu toggle. **F** is not fullscreen.
- Agent debug overlay: open `http://localhost:5173/?debug=1` (or `localStorage.blackoutDebug=1`). Players should not see this.

### Commands

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc && vite build (must pass before commit)
```

## Automation protocol (how to run a chunk)

When the human says "continue", "next chunk", "build the game", or similar:

1. **Read this file** and identify the first incomplete chunk in [Execution chunks](#execution-chunks).
2. **State the chunk** in one sentence (what will ship).
3. **Implement** that chunk (plus tiny fixes required for it). Use subagents when two tracks are independent; merge before commit.
4. **`npm run build`** - fix until green. No commit on red.
5. **Smoke-check** if relevant (controls, fps, no freezes).
6. **Update this file**: mark chunk `done`, note debts, set `CURRENT_CHUNK` to next pending.
7. **Mandatory: `git add`, `git commit` (message names the chunk id), `git push` to origin.**
8. If autopilot / finish phase: go to step 1 for the next chunk. Otherwise stop and report.

If a chunk is too large: split into A/B, commit A, then B.

### Commit message pattern

```
[5.1] Add checkpoint gate circuit near spawn

Short why/what body if needed.
```

### Autopilot modes

| Human says | You do |
|------------|--------|
| "next" / "continue" | One chunk |
| "keep going" / "autopilot N chunks" | Up to N chunks (default 3), stop on failure or ambiguity |
| "finish phase X" | All remaining chunks in that phase |
| "plan only" | Update plan here; no code |

## Creative direction (taste defaults)

When unspecified, choose:

- **Camera:** chase default; drama from speed juice, not spring lag
- **Difficulty:** easy takeoff, forgiving first landings, crash is funny not punishing
- **UI:** dark glass, muted cyan/grey, sparse; controls behind a button, not dumped on the title
- **World:** living day/night already; biomes varied; peaks sharp, foothills soft
- **Audio later:** low rumble engine, wind hiss, short boom on crash
- **Scope cut order:** cut 4.5 / 6.3 / 7.2 extras before cutting audio (7.1); never radar/weapons before the circuit is fun

### Definition of fun (acceptance)

A stranger can:

1. Load the page and pass the title screen  
2. Take off without a manual  
3. Fly a short **gate circuit** (once Phase 5 ships) or a scenic circuit  
4. Land or crash and restart  
5. Say "that was fun" after 2 minutes
