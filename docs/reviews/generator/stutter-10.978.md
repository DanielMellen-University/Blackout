A separate native Chrome diagnostic reproduces 283.4 ms. The main renderer thread spends 285.023 ms in compositor `Commit`, including 284.180 ms in `GLES2::ReadPixels` and 283.897 ms waiting for GPU commands. These nested times overlap. The enclosing readback, rather than a flight RAF JavaScript callback, accounts for the gap. No overlapping GC or shader compile span dominates this interval. Terrain generation, settlement assembly, hydrology, worker reply handling and texture publication are not its enclosing main-thread operation. The bounded native trace and attribution are in `stutter-profile/desert-run-42/`; the complete 30 MB compressed timeline remains local under that directory's ignore rule.

The separate final-context native diagnostic observes a 50.1 ms RAF maximum and a 23.882 ms maximum compositor readback, compared with 284.180 ms before. Its longest captured main-thread task is 58.476 ms. The final context confirms alpha false, antialiasing true and desynchronized true. This diagnostic is excluded from flight acceptance; its full trace is retained under `stutter-final-profile/`.

Production now requests `desynchronized: true` on the existing WebGL2 context. This selects the browser's existing low-latency canvas presentation path and avoids the blocking compositor snapshot in the observed browser. Antialiasing, depth, the original opaque alpha setting, power preference, every material, geometry, render distance, adaptive resolution rule and streaming budget remain intact. The browser can ignore the hint on other implementations. This is a presentation repair, with no route, terrain, record, physics, nitro, collision, water or gameplay change. The browser hint is described in [Chromium's canvas announcement](https://blog.chromium.org/2019/05/chrome-75-beta-low-latency-canvas.html).
